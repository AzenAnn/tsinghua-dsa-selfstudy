## 第 1 步：准备

1. Vector 是模板类，所以声明和实现都在 `include/dsa/vector.h` 一个文件里：前面是类的定义，后面按天分段，每个函数现在都是 `DSA_TODO();`。
2. 析构函数 `~Vector()` 的函数体现在是空的（析构函数里不能抛异常）；你要在里面释放 `_elem`，否则 AddressSanitizer 会报内存泄漏。

## 第 3 步：写代码（约 2 小时）

合上书，按下面的顺序写，每写完一个函数就运行一次测试：

1. 先写 `copyFrom`，再写 6 个构造函数（大多一行，调用 copyFrom）和析构函数。运行 `tools/test.sh ch02 D03`，“构造”那两个用例应通过。
2. 写两个 `operator[]` 和 `operator=`。`operator=` 要先判断是不是自己赋值给自己（`this != &V`），再释放旧空间、复制新内容。
3. 写 `expand`：空间不够时容量加倍（容量小于 DEFAULT_CAPACITY 时先设成 DEFAULT_CAPACITY），把旧元素逐个复制过去，再释放旧空间。
4. 写 `shrink`：容量不小于 2 倍默认容量、且装填因子不超过 25% 时，容量减半。
5. 运行 `tools/test.sh ch02 D03`，6 个用例都应通过。

全部完成时，这 6 个用例都显示 `[通过]`，每个测试程序的最后一行是 `通过 …，失败 0，待实现 0`。还没写的函数显示黄色的 `[待实现]`；写错的显示红色的 `[失败]`，下面跟着出错的那行测试代码和两边的实际值。

调试提示：

- “扩容是分摊 O(1)”这个用例统计了元素被赋值的总次数；不通过说明扩容不是加倍，或者复制了不该复制的东西。
- `heap-use-after-free`：通常是先 `delete[]` 了旧数组，后面又去读它。
- `memory leaks`：析构函数或 operator= 没有释放旧的 `_elem`。

实测复杂度：

- 运行 `tools/bench.sh ch02_expand`：每次插入的平均耗时应基本不随 n 增长。然后做一个实验：把 `expand` 里的 `_capacity <<= 1` 临时改成 `_capacity += 16`，重新运行这个计时程序，你会看到耗时随 n 线性增长；最后改回来。
